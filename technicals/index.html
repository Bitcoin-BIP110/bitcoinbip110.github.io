Chain identity

Replay protection and custody

SIGHASH_UNIFIED is opt-in

Ordinary signatures spending shared pre-fork outputs can remain valid on both histories. SIGHASH_UNIFIED uses hash-type bit 0x20 and tagged hash UnifiedSighash to provide one-way replay protection for signatures that opt in.

PropertyValue
Opt-in granularityPer signature
Covered script familiesBare/P2SH, SegWit v0, Taproot key path, Tapscript
Signer input dataValue and scriptPubKey of every spent output
Reference test vectors166
Normal withdrawal inventoryUse BIP110_ONLY outputs; exclude SHARED and UNKNOWN

BTC and BIP110 systems should use separate data directories, node processes, wallet databases, signer namespaces, deposit mappings, withdrawal queues, broadcast paths, and accounting asset IDs.
